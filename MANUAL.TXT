 PART 1    OVERVIEW
________________________________________

This reference describes the integrated
text editor included with the Nine IDE.
It was (and in many ways still is)
designed to operate on vintage
battery-operated hardware.  The editor
is very simple.  It holds just one
document and a backup.  Its width is
fixed at 40 characters.  There's no
horizontal scrolling and no word
wrapping, though the cursor does move
to a new line when a character is typed
at column 39.  See LINE WIDTH, Part 5.
Editing commands use a basic control
hotkey system.

The editor's text document is divided
into 100 "sections" of 100 lines each,
for a maximum of 10000 lines starting
from 0, ending at 9999.  Each section is
compressed on the fly.  A 32 to 35
kilobyte text document packs inside the
22000 byte memory space, give or take.
See Part 2 for details.

The editor tries to avoid accidental
destruction.  Overwrite mode applies to
typed characters only.  Everything else
inserts, including Enter.  Quitting,
loading or downloading prompts before
discarding modified work.

In the key tables below, "^" means Ctrl.
Named keys like Arrows, Home, End, PgUp,
PgDn, Del, Enter, Insert, Backspace and
Tab, all have a control-key counterpart,
and work where they are shown.  Either
form may be used.  A single control
letter is used for common actions, and
dual-key combos like "^Q ..." are used
for extended movement, and "^K ..." for
block and file commands.


________________________________________

 PART 2    SECTIONS
________________________________________

A document is one continuous text with
lines numbered from 0 to 9999.
Internally, the text is divided into 100
sections of 100 lines each:

    Section 0    lines 0..99
    Section 1    lines 100..199
    Section 2    lines 200..299
    ...
    Section 99   lines 9900..9999

Only one section is open in memory at a
time.  When the cursor leaves a section,
it is compressed and stored.  The
destination section is then unpacked.
Cursor movement, paging, and ^J all work

seamlessly across section boundaries.


SECTION COMMANDS

 ^K I               Insert empty
                    100-line section
                    at cursor
 ^K Y               Delete entire
                    section at cursor

Sections are inserted or deleted only as
complete 100-line units.  There are no
partial sections.


SECTION FULL

A section's last line (xx99) is "in use"
when it contains a character.  While
xx99 is in use, no new line can be
inserted into the section.  Pressing
Enter at the section's last available
line moves the cursor into the next
section instead of splitting.

       +---
 xx00  |
       |
       |
       |
       |   (no line inserting possible)
       |
       |
       |
 xx99  |    while 1 { // filled
       +---

Why?  In order to insert, line xx99
would need to be shoved into the next
section.  The Nine IDE does not have the
memory and speed to accomplish a series
of inserts through sections that must be
unpacked, modified, then repacked.
Workarounds include deleting individual
lines with ^Y, then undeleting with ^U
in the next section, or simply using
block copy.


INSERT SECTION

^K I inserts a whole empty 100-line
section, shifting all later sections
down by one.

If section 99 contains any characters,
even just one, the insert is refused
with "last section full".  The editor
will not push sections off into the
void.


DELETE SECTION

^K Y deletes the section containing the
cursor as a single 100-line unit,
shifting all later sections up by one.
If the section is not empty, the
message:

    Are you sure? _

will appear.  Only pressing 'Y' confirms
deletion.

 PART 3    THE STATUS OVERLAY
________________________________________

 ^O                 Toggle the status
                    overlay on or off

The bottom-right of the screen shows the
current position, available memory, and
editor state.

    L0000 C00 22000B ----

Reading left to right:

    L0000   line number, 0..9999
    C00     column number, 0..39
    22000B  available text memory
            in bytes
    ----    state indicators


The state indicators show four
characters:

    First:  Modified
        -   document is clean
        *   document was modified
            since last save or load

    Second: Overwrite
        -   overwrite mode off
        O   overwrite mode on

    Third:  Block copy
        -   no block activity
        ^   first mark set by
            pressing ^K B,
            awaiting second
            mark
        !   ^K B pressed again,
            block copied to
            clipboard, ready to
            paste with ^K C

    Fourth: Top section direction
        -   no document / empty
        <   top section is located
            before current section
        @   top section is located
            at current section
        >   top section is located
            after current section

The "top section" is the highest
numbered section that still holds text.
This indicator says where that section
sits relative to the cursor, so it
tells the typist at a glance whether
there is any material further on.  ^Q G
jumps straight to it.

The section number is not shown but is
computed by dividing the line number by
100 then rounding down:

    section = floor(line / 100)

Line 742 is in section 7, line 9950 is
in section 99, line 35 is in section 0.

The status overlay disappears when the
cursor moves into it, returns when the
cursor moves away.  Press ^O to toggle
it on or off.

 PART 4    CURSOR MOVEMENT
________________________________________

 ^E     Up          Up one line
 ^X     Down        Down one line
 ^S     Left        Left one column
 ^D     Right       Right one column
 ^A     ^Left       Word left
 ^F     ^Right      Word right
 ^R     PgUp        Page up
 ^C     PgDn        Page down
 ^W                 Scroll up
 ^Z                 Scroll down

 ^Q S   Home        Start of line
 ^Q D   End         End of line
 ^Q E   ^Home       Top of page
 ^Q X   ^End        Bottom of page
 ^Q R   ^PgUp       Top of section
 ^Q C   ^PgDn       Bottom of section
 ^Q G               Go to last full
                    section

 ^J                 Jump to a line

^J prompts for an absolute line number
from 0 to 9999.

Cursor movement is seamless across
section boundaries.  The editor
compresses the outgoing section and
unpacks the destination as needed.
Slower computers may experience a slight
delay when traversing filled sections.


________________________________________

 PART 5    EDITING TEXT
________________________________________

CHARACTER INPUT

Typing inserts characters within a line
of text.  Text at and after the cursor
shifts right to make room, so an insert
is only possible when column 39 of that
line is blank.  A line's remainder never
forces itself into the next line.

          1    1    2    2    3    3
0    5    0    5    0    5    0    5
|----|----|----|----|----|----|----|----

         (no inserting possible)       X
                                       ^
                                       |
                                (filled)

Why?  Since there are no newline
terminators (Part 2), a character pushed
off column 39 would have to be pushed
into the line below, and that line's
last character into the line below it,
and so on through the end of the section
and into the next.  The editor has no
way to tell where such a run of text was
meant to end.


OVERWRITE

 ^V     Insert      Toggle insert

Overwrite mode applies to typed
characters only.  When this mode is
activated, typed characters overwrite
text at the cursor, then advance the
cursor by one character space.  All
other editing commands operate the same
way regardless of the current mode.


LINE WIDTH

Lines may not exceed 40 characters.
When the typist inserts a character at
column 39:

  * If the section's last line
    (xx99) is empty, the
    editor inserts a new line
    and the cursor wraps to
    column 0 of the new line.

  * If the section's last line
    is not empty, the cursor
    halts at the right margin
    and the character there is
    not overwritten.

In overwrite mode, typed characters
simply replace characters at the
cursor's position.


TABS

 ^I    Tab          Advance to next
                    tab stop
 Shift+Tab          Move to previous
                    tab stop
 ^K W               Set tab width

Tab inserts spaces, not a tab character.
Tab width is set with ^K W, prompting:

    tab width: _

Tab width must be in the range 2 to 20
(half the screen width).  2 is the
default width.

Shift+Tab is non-destructive.  It moves
the cursor to the previous tab stop only
if no character is in the way.  If there
is a character, the cursor stops at the
obstructing column.


ENTER AND AUTO-INDENT

 ^M     Enter       Split line at
                    cursor

Enter inserts a new line below the
cursor, and splits the line into the
next.  If the last line of the section
contains a non-blank character, or, if
the typist presses Enter on the
section's last line, the cursor will
proceed to the next line but NOT split

the last.

A new line's leading spaces match the
previous line's indentation.  In other
words, the cursor lands at the same
column as the first non-blank character
above.  Pressing Enter on an otherwise
empty line moves the cursor to column 0.

    func draw_box()
    {
        var width_

        ^
        |
   (lands here)


DELETION

 ^H     Backspace   Delete left
 ^G     Del         Delete right
 ^T                 Delete word
 ^Y                 Delete line

Backspace removes the character to the
left of the cursor.  Del removes the
character under the cursor.  Both shift
the remaining characters left.  If the
cursor lies on column 0, pressing
backspace returns the cursor to the
previous line, dragging the current
line's contents with it IF there is
enough room to do so.

Backspace will not drag text across a
section boundary.


WORD DELETION

^T deletes from the cursor through the
next word and any trailing whitespaces.
If the cursor is on a non-alphanumeric,
non-whitespace character (e.g. "$" or
"&"), only that single character is
consumed.


LINE OPERATIONS

 ^Y                 Deletes current
                    line
 ^U                 Undo line delete
                    (see Part 8)
 ^N                 Insert blank line
                    below current
 ^B                 Duplicate the
                    current line below

 PART 6    FIND TEXT
________________________________________

 ^Q F               Find
 ^L                 Find again

^Q F prompts:

    find: _

Type the string to locate and press
Enter.  Find is case-sensitive and does
not wrap around.  It runs forward from
the cursor's position to the end, then
stops.  A lone space is not a valid
search string.

^L repeats the last search from the
cursor's position, forward only. There
is no wrap.

If the search string is not found, the
editor displays:

    string not found

The cursor stays where it was.

 PART 7    BLOCK COPY
________________________________________

To copy a block:


  1. Move the cursor to the
     first line of the block
     and press ^K B.  The mark
     is set and the indicator
     shows "^".

  2. Move the cursor to another
     line of the block
     and press ^K B again.  The
     block is captured into
     the clipboard and the
     indicator changes to "!".

  3. Move the cursor to the
     destination and press ^K
     C.  The clipboard contents
     are inserted at the
     cursor.

A captured block stays in the clipboard
and can be pasted multiple times in any
section, even where the block did not
originate.


COMMANDS

 ^K B               Mark / capture
                    block
 ^K C               Paste block at
                    cursor
 ^K X               Cancel block
                    operations


THE BLOCK STATE

The block subsystem has three states,
shown by the third character of the
status indicator:

    -   no top mark, no
        clipboard contents.
    ^   first mark is
        set, waiting for the
        second mark.
    !   a block is in
        the clipboard, ready
        to paste.

^K B toggles through the states.  "^"
indicates the first line, "!" the
second.  The first and second line may
be the same line.  The second line may
be marked above the first.

^K X cancels at any time, returning the
state to "-".


CONSTRAINTS

A marked block may not span sections.
If the first mark is in section 5, the
second ^K B must also be in section 5.
Pressing ^K B in a different section
gives the error:

    invalid text block

The armed state is cleared and the
indicator returns to "-".

A paste destination may not span
sections either.  Pasting near the end
of a section where the block would not
fit, or, if no room exists to insert
the block, gives the error:

    cannot copy text

Block copy always inserts.  No action
occurs if copying would push any text
below it past a section's boundary.

The clipboard is not cleared by this
error.  The user can navigate to a
section with enough room and try ^K C
again.

Maximum block size is 100 lines (the
size of one section).


COPYING ACROSS SECTIONS

A block captured in one section can be
pasted in any other section, provided
the destination section has room.  Only

the marking step is restricted to a
single section, the paste step is not.


RESET

The clipboard is erased with a prompted
confirmation before compile (^K T) and
run (^K R) if temporary storage is not
available (see Part 10).

  Erase clipboard?

The mark state (^) (the first mark) is
also reset if a line is inserted above
the marked line, or, a section is
inserted or deleted before the marked
line's section.

The clipboard (!) and mark state (^) is
not cleared by saving or uploading.
Loading or downloading clears the mark
state (^) only.


________________________________________

 PART 8    UNDO
________________________________________

Lines deleted with ^Y can be restored
with ^U.


COMMAND

 ^U                 Restore the most
                    recently deleted
                    line at the
                    cursor position


BEHAVIOR

Deleted lines are kept in a "LIFO"
buffer; Last In, First Out.  ^U removes
the most recent deletion and inserts it
at the cursor's current line position.

The undo buffer holds up to 100 lines.
Additional deletions push out the oldest
entries.


CROSS-SECTION

^U works across section boundaries but
will not insert a line that would push
content past a section boundary.  If the
current section is full (xx99 in use),
^U silently does nothing in the same way
any insert-line operation does.  The
deleted line remains in the undo buffer
for a later attempt.


RESET

The undo buffer is cleared with a
prompted confirmation before
compile (^K T) and run (^K R) if
temporary storage is not available.
The undo buffer is not cleared by
saving, loading, uploading or
downloading (see Part 10).


________________________________________

 PART 9    FILE OPERATIONS & TRANSFER
________________________________________

The editor currently maintains two
files, the working file and a backup
file.  There are no filenames and no
directories.  The document is saved to a
fixed location.


COMMANDS

 ^K N               New

 ^K L               Load file
 ^K O               Load backup
                    (old) file
 ^K S               Save file

 ^K U               Upload

 ^K D               Download

 ^K Q  Esc          Quit


NEW, LOAD, QUIT

^K N, ^K L, ^K O and ^K Q prompt for
confirmation if the document has been
modified since the last load or save.
An unmodified document is replaced or
closed without prompting.

^K N completely erases the current
document and places the cursor in the
home position at section zero.  The
clipboard and undo buffers remain
intact.


SAVE

^K S writes the document to storage
immediately.  There is no filename
prompt.


BACKUP

^K O loads the backup document.  There
is no saving to it.  During a save (^K
S), the backup file is overwritten with
the file saved earlier.


UPLOAD AND DOWNLOAD

^K U sends the document over the serial
port.  ^K D receives a document over the
serial port, replacing the current
contents.

Transfers are direct between the
editor's text buffer and the serial
line.  There is no intermediate file.

The serial port runs at 9600 bps, 8N1
(see Language Reference, Part 8).

Press Esc or ^Break to terminate
the transfer.


________________________________________

 PART 10    BUILD AND RUN
________________________________________

COMMANDS

 ^K T               Compile only
 ^K R               Compile and run

 ^Break             Stop compilation
                    or run


COMPILE ONLY

^K T compiles the document without
executing it.  On success, the editor
reports the build size at the bottom of
the screen as a single line:

Code: 00006, Data: 00000, Free: 16378

The numbers are byte counts of the
generated code, the accumulated data
area, and the remaining free memory.
The "free" memory indicates the
available stack space.  Stack space
shrinks as code and data grow.

On failure, the compiler reports the
first error at the bottom of the screen.
Press Enter to jump to the error (if not
already there).  Press Esc or Space to
return to the previous cursor position.
All other key presses are ignored.


COMPILE AND RUN

^K R compiles the document and, on
success, executes it.

Runtime errors are not tracked back to
source.  A runtime error halts the
program and displays the memory address

and message.  The cursor returns to the
editor at the position it was at before
the run.


BREAK

Pressing ^Break stops compiling or
a running program with a message:

    LXXXX: break

LXXXX is the line number where the break
occurred.

    0xXXXX: break

0xXXXX is the runtime break address.


SIDE EFFECTS

^K R and ^K T reset the clipboard and
undo buffers (see Parts 7 and 8) if
temporary space in the text memory area
is not available.  The clipboard and
undo buffers use code memory as storage.
Before compiling begins, the IDE tries
to preserve them by moving a compressed
version of each into leftover text
memory with priority given to the
clipboard.  Two prompts appear if either
cannot fit.

  Erase clipboard?
  Erase undo?

Pressing any key but 'Y' aborts the
compile or run, and both erasures (even
if 'Y' was chosen on the first.)

 PART 11    MEMORY LIMITS
________________________________________

The editor has a fixed text memory
budget.  Sections are compressed when
not in use.  The effective document
capacity is roughly 1.4 times raw text
memory, or about a 65 to 70% compression
ratio.


SECTION TRANSITIONS

When the cursor leaves a section, the
editor must compress and store it.  If
memory is too tight to do so, the editor
refuses to navigate out of the section
and displays:

    out of text memory

The user is locked into the current
section until enough space is freed.
Every form of cross-section movement is
blocked equally, including arrows,
paging, ^J, and even save (which also
needs to compress the current section).

To recover:

  * Trim text in the current
    section, then navigate
    out, confirming enough
    space is available.

  * Reduce tab widths and
    left margin lengths.

  * Pack code together
    tightly.  Shorten
    identifiers and remove
    spaces.

  * Delete the entire section
    with ^K Y.

Quitting (^K Q) is always allowed.  If
the document is modified, the editor
still prompts to save first, but the
user may answer no and exit without
saving.


OUT OF TEXT MEMORY VS. SECTION FULL


Two related but distinct errors:

    "out of text memory" not
    enough free memory to
    compress and store the
    current section.

    "last section full" ^K I
    attempted while section 99
    contains content.


PEEK EEPROM ADDRESS

 ^K P               Peek EEPROM
                    address

Pressing ^K P prompts for a base-10
EEPROM address from 0 to 511.

   address: _

Pressing Enter reveals the contents of
that address.

    000 (0x00): 00000 (0x0000)_

"EEPROM" is an area of 512 16-bit
nonvolatile memory locations used to
store permanent data.  See Language
Reference, Part 8.  The programmer is
free to modify the memory's contents.
Reading outside the address space
triggers the error:

  invalid EEPROM address

________________________________________

 PART 1    OVERVIEW
________________________________________

This reference describes the Nine
programming language.  It's a typeless,
procedural programming language where
every value is a signed 16-bit word
stored in little-endian format.  There
are no other data types.  Addresses,
strings, characters, scalars, arrays and
function pointers are all numbers.
There is no type-safety and no array
bounds checking.  Extensive guards are
in place to ensure stack, code and data
overruns produce meaningful runtime
error messages.

This document is not meant to be a
programming tutorial.  It is assumed the
reader already has an understanding of
basic programming concepts.


________________________________________

 PART 2    MEMORY MODEL
________________________________________

Address space is 16384 bytes, from
0x0000 to 0x3FFF.

Code grows upward from the bottom of
memory.  Data (globals, string literals,
anonymous array and anonymous expression
function literals) grows downward from
the top.  The stack fills the gap
between them.

    0x3FFF  +-------------+
            |    data     |
            |      |      |
            |      v      |
            +-------------+
            |             |
            |    stack    |
            |             |
            +-------------+
            |      ^      |
            |      |      |
            |    code     |
    0x0000  +-------------+


All values are 16-bit signed integers
(-32768 to 32767).  One character is one
16-bit integer.

Memory is addressed in bytes, but
indexing through [ ] is word-scaled.
The array arr[i] lives in byte address
arr + i * 2.


________________________________________

 PART 3    LEXICAL ELEMENTS
________________________________________

COMMENTS

Block comments use /* ... */ and do not
nest.

  /* this is a
     block comment
  */

Line comments use //.

  // this is a line comment


IDENTIFIERS

Identifiers (names) start with a letter
or underscore, followed by letters,
digits, or underscores.  Maximum length
is 16 characters.

  n       byte_count  _next_free
  crc16   MAX_RETRIES
  Huge_Identifier1

Identifiers are case-sensitive.
Shadowing is not allowed, meaning that
an inner declaration cannot reuse a name
from an enclosing scope.  Identifiers
cannot share the same name as the
language's built-in keywords:

  break       const
  continue    dec
  do          else
  enum        func
  if          inc
  leave       let
  loop        return
  var         while


NUMERIC LITERALS

  42              /* decimal     */
  0xBEEF          /* hexadecimal */
  0o777           /* octal       */
  0b10110100      /* binary      */
  'A'             /* character   */
  '\n'            /* escape   */

All numeric literals produce a 16-bit
signed value.  Values that don't fit
wrap silently.

  0b10000000000000001 = 1
  0o7654321           = 22737
  12345678            = 24910
  0xabcdef            = 0xcdef


CHARACTER LITERALS

A character literal contains exactly one
character or escape sequence between
single quotes:

  'a'   '!'   '\n'   '\x541'

Multi-character forms such as 'ab' are
invalid.


CHARACTER ESCAPES

Character and string escapes:

  '\0'  '\a'  '\b'  '\e'
  '\n'  '\r'  '\t'  '\v'
  '\\'  '\''  '\"'
  '\xXXXX'

The \x escape consumes all hex digits
(0-9, a-f, A-F) up until there are no
more.  A value of \xABCD123 wraps to
D123.


STRING LITERALS

  "Hello, world\r\n"

A string literal evaluates to the
address of its first character.  Strings
are stored as null-terminated word
arrays in the data area, one 16-bit
integer per character.  Maximum length
is 128 characters, including the
null-terminator.

  const PROMPT = "Ready"

  /*
  PROMPT is the address:
  PROMPT[0] = 'R', PROMPT[5] = 0
  */

Adjacent string literals are joined
(concatenated) at compile time.  A
string may span lines:

  let banner =
    "Nine IDE v1.12\r\n"
    "Press Esc to quit\r\n"

String literals are "mutable".  Unlike
local scalars and arrays with defined
sizes which are reinitialized on each
function call, a string is placed in the
data area once at compile time and
shared across all calls.

  func log_line()
  {
    var msg = "0: ready\r\n"

    put_str(msg)
    inc msg[0]
  }

Prints

0: ready
1: ready


A change to a string persists for the
rest of the run, even if the literal
appeared inside a function.  String
literals are static data, not fresh
locals.

Identical strings are not merged.  All
strings are considered unique and occupy
their own place in memory.


ANONYMOUS ARRAY LITERALS

  {1, 2, 3}

The "sum" example:

  func sum(arr, size)
  {
    var total

    while size {
      dec size
      let total = total +
                  arr[size]
    }

    return total
  }

  func main()
  {
    // five quiz scores, 400
    var total = sum({88, 92, 75,
                     71, 74}, 5)

    put_str("Total: ")
    put_int(total)
  }


Like all global arrays (anonymous or
not), an anonymous array literal
evaluates to the address of its first
element, the same way a string literal
evaluates to the address of its first
character.  Elements are stored as one
16-bit word each in the data area.

  const COIN = {1, 5, 10, 25}

  /*
  COIN is the address:
  COIN[0] = 1, COIN[3] = 25
  (COIN + 1)[0] = 1280
  */

Like strings, anonymous array literals
are "mutable" and are placed in the data
area once at compile time:

  func record(score)
  {
    var best = {0, 0, 0}

    if score > best[0]
      let best[0] = score

    /*
    this particular literal
    keeps the high score for the
    rest of the run, even though
    it was written inside a
    function
    */
  }

Identical anonymous arrays are not
merged.  Each occurrence is considered
unique and occupies its own place in
memory.

Every element must itself be a constant
expression.  See CONSTANT EXPRESSIONS,
Part 6.  Literals may nest to build
jagged rows; see Part 4.


PARENTHESES AND LEADING BRACES

When an anonymous array literal is the
first thing in a statement, it needs a
nudge.  It must be wrapped in
parentheses or lead with a unary
operator such as '+'.  A bare leading
'{' is otherwise read as the start of a
block statement (see Part 5), not as a
literal:

  {
    // some code
  }

  // will cause an error
  {31, 28, 31, 30}[month()]

  /*
  parentheses force it to
  be read as an expression
  */

  ({31, 28, 31, 30})[month()]

This comes up naturally with a table of
function pointers, indexed then called
in one expression:

  func do_new()  { /* ... */ }
  func do_open() { /* ... */ }
  func do_save() { /* ... */ }
  func do_quit() { /* ... */ }

  func menu(choice)
  {
    ({do_new, do_open,
      do_save, do_quit,})[choice]()
  }

Or, by doing away with named functions
and using anonymous expression
functions instead (See Part 6)

  func menu(choice)
  {
    ({ func () { /* do_new */ },
       func () { /* do_open */ },
       func () { /* do_save */ },
       func () { /* do_quit */ },
    })[choice]()
  }

Here the parentheses are required for
the same reason.  The statement would
otherwise begin with '{' and be read as
a block of code and not as an array.
Once inside an expression, such as on
the right side of a 'let' or as part of
a declaration initializer, the ambiguity
does not arise because an expression is
expected.

  /*
  Fine without parens because
  the statement doesn't begin
  with '{'
  */

  let action =
    {do_new, do_open,
     do_save, do_quit,}[choice]

  // no error
  return {-1, 0, 1}[cmp + 1]

  // error
  leave {-1, 0, 1}[cmp + 1]

  // no error
  +{-1, 0, 1}[cmp + 1]


STATEMENTS THAT START WITH *

The star, as a unary operator is used to
modify or access the valued stored at a
specific address in the same way the
square bracks do.

A statement that opens with * has the
same trouble as one that opens with a
brace.  Nothing separates one statement
from the next, so the * is read as
multiplication against the line above:

  let a = b
  *c[0]        // reads as
               // let a = b * c[0]

This rarely happens in practice.  A bare
*p on its own is useless.  There is no
reason to write one.  Every statement
that does real work through a * begins
with "let", "inc" or "dec", and those
leave no room for confusion:

  let *p = 10
  inc *p

VARIABLES (var)

  var count
  var retries = 5
  var line_buf[40]
  var rgb[3] = {255, 128, 0}
  var level[5] = {1, 2}
  var x, y = 2, path[4], hp = 7
  var coin[3] = {1, 5, 10,}
  var report[7] = {
    "Sensor",
    " offline",
    23 + BASE_ID,
    "12:00:00" + 2,
    on_alarm + BASE_ID,
    &last_reading,
    func () return 123,
  }
  var handlers = {rgb, on_alarm}

Example #1

  var msg[3] = {
    "Hello ",
    "World" + 4,
    "Fantastic!" + 22
  }

  func show_parts()
  {
    // displays "Hello rld"
    put_str(msg[0])
    put_str(msg[1])

    /*
    displays "World" because
    "World" resides at a
    higher memory address
    than "Fantastic!"
    */
    put_str(msg[2])

    // displays "tastic!"
    put_str(msg[2] - 16)
  }

Example #2

  var volume = 123

  func show_volume()
  {
    var slot[1] = { &volume }

    // prints 123
    put_int(slot[0][0])

    /*
    also prints 123
    (and uses less memory)
    */
    put_int(**slot)
  }

Partial array initializers leave
remaining elements as 0.  Too many
elements results in the error

  too many elements

  var mon_days[3] = {31, 28, 31, 30}
  // error

Trailing commas are allowed.

  var mon_days[4] = {31, 28, 31, 30,}

Multidimensional array declarations are
not permitted, however multiple bracket
dereferences are.

  var mon_days[3] = {31, 28, 31}

  func march_days()
  {
    var q1[3] = {0, mon_days, 0}

    // returns 31

    return q1[1][2]
  }

  var keypad[5] = {
    { '1', '2', '3', 'A', },
    { '4', '5', '6', 'B', },
    { '7', '8', '9', {'C',0,0}},
    // last two elements are 0
  }

  func extra_key()
  {
    /*
    prints 67, the
    code for 'C'
    */
    put_int(keypad[2][3][0])
    /* or
    // put_int(*keypad[2][3])
    */
  }

Anonymous array literals (Part 3) nest
the same way, without needing to declare
and name each row first.  Because each
literal is itself a constant expression,
one can appear as an element of another.

  // 3x3 magic square

  var square = {
    {2, 7, 6},
    {9, 5, 1},
    {4, 3, 8},
  }

  // prints 1
  put_int(square[1][2])

square holds the address of a 3-element
block of pointers, one per row.
square[1] dereferences that block and
returns the address of {9, 5, 1}.
square[1][2] then dereferences that
address at offset 2.  The result is a
jagged structure, not one contiguous
block, since each row is its own
separately placed literal in the data
area.

Global scalar initializers must be
constant expressions.  Local scalar
initializers may be any expression:

  // global constant only
  var margin = 1 + 2 * 3
  var row2 = SCREEN_MEM + 40

  // local expression
  func draw_row()
  {
    var key = wait_key()
    var cell = screen[key]
  }

Without initializers, both global and
local scalars and arrays default to
zero.

Array subscript definitions may not be
negative, zero or empty.  Array
subscripts and initializers (global or
local) must be constant expressions.
Why?  Global and local arrays are given
a fixed spot in memory (see Part 2)
before the program runs.  There is no
way to grow that space at runtime.  The
compiler needs a size it can resolve on
its own.

  func build_table()
  {
    var rows = 123

    // error, can't be zero
    var empty[0]

    // error, empty subscript
    var nosize[]

    // too big
    var huge[8192]

    // error: stack overflow
    var less_huge[8191]

    /*
    error, not a
    constant subscript
    expression
    */
    var sized[rows]

    // no can do
    var seeded[10] = {rows}

    // good, no error
    var addrs[10] =
        {hex_chars, put_int + 2,
         6, &"ABC"[3]}

    // ok but weird
    var odd[&put_int[99]]

    // good, value = 1
    var mid = {1, 2, 3} + 2
    var value = mid[-1]
  }

Just like local variable declarations,
local arrays declared with a size are
reinitialized on every call.  They are
"copied" into the frame, and are not
persistent the way strings and
anonymous arrays are.

  func fresh()
  {
    var hits[3] = {0, 0, 0}

    // always prints 0
    put_int(hits[1])

    inc hits[1]
  }

  func start()
  {
    // prints 00
    fresh()
    fresh()
  }

Compared with this example:

  func shared()
  {
    var hits = {0, 0, 0}

    put_int(hits[1])
    inc hits[1]
  }

  func start()
  {
    // prints 01
    shared()
    shared()
  }

UNDEFINED BEHAVIOR

Reading or writing to an array from
outside its defined boundary results
in undefined behavior.

  func not_good()
  {
    var bad_arr[3] = {1, 2, 3}

    // may cause runtime error
    let bad_arr[3] = 456
  }

Writing to any random memory location
without knowing what's there may also
result in undefined behavior.

  func main()
  {
    let 171[4] = 0xDEAD
  }


FUNCTIONS (func)

  func reset() { ... }

  func zero() return 0

  func add(a, b) return a + b

  func ignore(a, b) { leave }

  func max(a, b)
    { ... }

  func outer()
  {
    func inner()
    {
    }

  }

  var plus = func (a, b)
      return a + b

  func main()
  {
    var fib
    let fib = func (n)
    {
      if n <= 1
        return n
      return fib(n - 1) + fib(n - 2)
    }
  }

A function body is either a single
statement or a brace-enclosed block.
Single-statement bodies need no braces.

Recursion is supported.  Locals are
fresh on every call.  Scalars and sized
arrays are reinitialized from their
declarations.

A local declaration inside a loop body
is reinitialized on every iteration,
not once per call.

Parameter counts are not checked at
compile time.  When a function is called
with fewer parameters than it was
declared with, the missing parameter
values default to zero.  When a function
is called with more, the extra
parameters are ignored.  A function may
have a total of 127 parameters.

  func add(a, b)
  {
    return a + b
  }

  func main()
  {
    // prints 10
    put_int(add(4, 6))
    new_line()

    // prints 7
    put_int(add(7))
    new_line()

    // prints 1057
    put_int(add(33, 1024, 76))
    new_line()

    // prints 0
    put_int(add())
    new_line()
  }

The last top-level function declared is
the program's entry point.  Functions
may be nested.

  func start()
  {
    func inner1()
    {
    }
  }

UNDEFINED BEHAVIOR

Calling a nested function from outside
its defined scope results in undefined
behavior.  A nested function may only
outlive its enclosing call if it
captures no local variables.

  var func_ptr

  func nice_func()
  {
    func bad_func()
    {
      var arr[1000], i

      while i != 1000 {
          let arr[i] = 0xFAF0
          inc i
      }
    }

    let func_ptr = bad_func
  }

  func start()

  {
    // may cause runtime error
    func_ptr()
  }


ANONYMOUS EXPRESSION FUNCTIONS

Expression functions are unnamed
(anonymous) blocks of code that may
appear anywhere in a constant or runtime
expression.  "func" acts as a unary
operator which yields its address.

  var add = func (a, b)
  {
    return a + b
  }

  func start()
  {
    /*
    call address stored
    in "add"
    */

    // print 77
    put_int(add(33, 44))

    wait_key()
  }

Expression functions may include other
expression function definitions, but may
not include statement (named) function
definitions.

  var outer = func ()
  {
    var inner = func ()
    {
      return read_timer()
    }

    // error
    func named()
    {
      // not allowed in here
    }
  }

Because they're unnamed, recursing
expression functions require a
workaround.

  var fact = func (n, fn)
  {
    if n <= 1
      return 1

    return n * fn(n - 1, fn)
  }

  func start()
  {
      // prints 6
      put_int(fact(3, fact))
  }

Another example...

  func start()
  {
    var power
    let power = func (b, e)
    {
      if e <= 0
        return 1

      return b * power(b, e - 1)
    }

    // prints 1024
    put_int(power(2, 10))
  }

The variable "power" holds the address
of the expression, but the name itself
is not visible inside the function.  The
right side of = must fully exist before
the variable on the left can hold it.

  func start()
  {
    var power = func (b, e)
    {
      if e <= 0
        return 1


      return b * power(b, e - 1)
      // name not defined
    }

    put_int(power(2, 10))
  }

Expression functions may appear in named
or anonymous arrays.

  enum {
    OP_NOT, OP_NEG, OP_ADD,
    OP_SUB, OP_MUL, OP_DIV,
    OP_MOD,
  }

  func dispatch(idx, n1, n2)
  {
    return {
     func (a) return ~a,
     func (a) return -a,
     func (a, b) return a + b,
     func (a, b) return a - b,
     func (a, b) return a * b,
     func (a, b) return a / b,
     func (a, b) return a % b,
    }[idx](n1, n2)
  }

  func start()
  {
      /* prints 15 */
      put_int(dispatch(OP_NEG, -3) +
              dispatch(OP_MUL, 2, 6))
  }

As mentioned earlier, "shadowing" is not
allowed.

  func (a)
  {
    if !a {
       var a = 123
       // error: name already defined
    }
  }

However, the following nested anonymous
function declaration IS perfectly legal
because the outer function "my_func" is
not yet defined completely.  Function
expressions cannot see the variable they
are being assigned to during the
definition.

  func start()
  {
    var my_func = func ()
    {
      var my_func = func ()
      {
      }

      my_func()
    }

    my_func()
  }

Compared with:

  func start()
  {
    var my_func

    let my_func = func ()
    {
      // name already defined
      var my_func = func ()
      {
      }

      my_func()
    }

    my_func()
  }

UNDEFINED BEHAVIOR

Calling an nested anonymous function
from outside its defined scope results
in undefined behavior.

  func my_count()
  {
    var count = 123
    return func () return count
  }

  func start()
  {
    put_int(my_count()())
    // will not print 123
  }

Another example:

  var func_ptr

  func nice_func()
  {
    var arr[1000]

    var bad_func = func ()
    {
      var i

      while i != 1000 {
          let arr[i] = 0x0FAF
          inc i
      }
    }

    let func_ptr = bad_func
  }

  func start()
  {
    // may cause runtime error
    func_ptr()
  }


CONSTANTS (const)

  const MAX_ROWS = 100
  const LO = 1, HI = 9, SPAN = HI - LO
  const SCALE = func (n, num, den)
  {
      return n * num / den
  }

The right side of each = must be a
constant expression.  A const is not a
storage location and has no address.


ENUMS (enum)

  enum { LEFT, RIGHT, CENTER }
  enum { OFF, ON, HOLD = 10, AUTO }
  enum { MON, TUE }, { JAN, FEB }
  enum { NORTH, SOUTH, }
  enum {
      NEG = func (a)    return -a,
      ADD = func (a, b) return a + b,
  }

Within a group, values auto-increment
from the previous enumerator (starting
at 0).  An explicit "= expr" resets the
counter.  Multiple groups may appear in
one declaration, separated by commas.
Each { } group starts its own count
at 0.


LOCAL DECLARATIONS

var, const, enum and func declarations
may appear anywhere inside a function
body, not only at the top, and follow
all standard scoping and comma chaining
rules.

  func mixer() {
    var vol = 5, band[3] = {1, 2, 3}

    const STEP = 4

    enum { LOW, MID, HIGH }

    func load()
    {
      var preset[10]
    }

    load()

    /*
    preset out of scope
    here
    */

    /*
    two separate chained
    function declarations
    with equal scope

    */

    func fade_in()
    {
      // ramp volume up
    }, fade_out()
    {
      // ramp volume down
    }

    /*
    declares stop
    inside play
    */

    func play() func stop() {}
  }

BLOCK

  {
    put_str("Ready")
    new_line()
  }

A statement beginning with '{' is always
read as a block.  An anonymous array
literal (Part 3) in that position needs
parentheses to avoid this.  See
PARENTHESES AND LEADING BRACES.


LOCAL DECLARATION

See Part 4.


ASSIGNMENT (let)

  let hp = 5
  let hp = 5, mp = 23
  let grid[i] = hp + 1
  let *(base + off) = value
  let row(y)[x * 3] = c,
      first = (1, grid)[3]

The left side of the equal (=) must
denote storage, such as a bare scalar
name or any expression ending in [...].
Assignments are statements, not
expressions.  Chained assignment is not
supported.

  let x = y = z      // error

  let y = z, x = y   // okay


COMPOUND ASSIGNMENT OPERATORS

A compound assignment operator
combines
binary or bitwise math with an
assignment.  They update the variable
after performing the operation using
its current value and a new value.

"let" may use any of the following
11 compound assignment operators:

  |=   ^=   &=
  +=   -=
  <<=  >>=  ~>=
  *=   /=   %=

The following statement pairs are
identical.

  let flags = flags & ~1
  let flags &= ~1

  let x_pos = x_pos + 1
  let x_pos += 1

  let matrix[i] = matrix[i] * scalar
  let matrix[i] *= scalar

  let crc = crc ^ b << 8
  let crc ^= b << 8


Compound assignment operators use less
code and text, and are less readable.


ASSIGNMENT (inc and dec)

  inc score
  dec lives
  inc score, bonus
  dec ammo[2], shields
  inc add2, add2

"inc" and "dec" are shorthand for
increment and decrement, and function
the same way as an incremental let:

  let score = score + 1
  let health += 1
  let lives = lives - 1
  let score = score + 1,
      bonus = bonus + 1
  let ammo[2] -= 1,
      shields -= 1

Both inc and dec use 10 fewer bytes of
code than let (without compound
assignments operators.)  Even with:

  let ticks = ticks + 2

using inc twice still uses less memory.

  inc ticks inc ticks

or even

  inc ticks, ticks

Break-even is at three (or negative
three), where both let and inc/dec use
the same amount of code space.


IF / ELSE

  if cond
    statement(s)

  if cond
    statement(s)
  else
    statement(s)

The if-statement executes the following
code block if cond (an expression)
evaluates to non-zero, and skips it if
zero.  The body may be a single
statement or an enclosed block.  The
optional "else" statement binds to the
nearest preceding "if".  See ELSE
BINDING below.


WHILE / ELSE

  while cond
    statement(s)

  while cond
    statement(s)
  else
    statement(s)

The while statement executes the
following code block continuously if
cond evaluates to non-zero, and skips it
if zero.  The body may be a single
statement or an enclosed block.  The
optional "else" statement binds to the
nearest preceding "while".  See ELSE
BINDING below.

  var i

  while i < 5 {
    inc i
    put_int(i)
    new_line()
  }
  else
    put_str("Done!\r\n")

Prints:

1
2
3
4
5
Done!

The "else" block runs when the loop

ends because cond became zero.  This
includes the case where cond was zero
on the very first test and the body
never ran at all.

A "break" exits the loop AND skips the
"else", jumping past both.  This makes
"else" the "ran out of items" branch:

  var i

  while i < len {
    if key[i] == want
      break

    inc i
  }
  else
    put_str("no match\r\n")

"continue" does not skip the "else".
It begins the next iteration, and the
"else" still runs once cond finally
becomes zero.


ELSE BINDING

Both "if" and "while" accept an optional
"else".  An "else" binds to the nearest
preceding unclosed "if" or "while",
whichever is nearer.

  if a
    while b
      statement(s)
  else
    statement(s)   // binds to WHILE

  while a
    if b
      statement(s)
  else
    statement(s)   // binds to IF

  if a {
    while b
      statement(s)
  }
  else
    statement(s)   // binds to IF

  while a {
    if b
      statement(s)
  }
  else
    statement(s)   // binds to WHILE


DO-WHILE

  do
    statement(s)
  while cond

Do-while loops operate as expected,
repeating statement execution until the
condition is false.

A do-while loop does not accept an
"else".  The trailing "while cond"
closes the statement, so an "else"
after it has no owner:

  misplaced else


LOOP

  loop
    statement(s)

Loop executes the following code block
continuously.  The body may be a single
statement or an enclosed block.  The
statement is equivalent to "while 1".

  var i

  loop {
    inc i

    if i == 5
      break
  }

  put_int(i) // prints 5


"loop" does not accept an "else"
either.  A "loop" ends only through
"break", and "break" skips the "else",
so the block could never run.  An
"else" after "loop" also produces:

  misplaced else


RETURN

  return expr

The return statement evaluates expr to
a runtime value, terminates the current
function immediately and passes the
value back to the caller's execution
context.

"return" always requires an expression.
To exit a function without a value, use
"leave" instead.

  func line_height()
  {
      return 1 + 1
  }

  func main()
  {
     // prints 2
     put_int(line_height())
     wait_key()
  }

The comma operator needs parentheses
after "return", the same way it does in
an expression statement.

  return (new_line(), total)


LEAVE

  leave

The leave statement terminates the
execution of the current function
immediately.  It takes no expression,
evaluates to zero, and restores the
caller's execution context.

A function that reaches the end of its
body without "return" or "leave" also
returns zero.  Every exit path yields a
defined value.

  func beep()
  {
      // nothing to report
      put_char('\a')
      leave
  }

  func main()
  {
      // prints 0
      put_int(beep())
      wait_key()
  }


BREAK

  break

The break statement exits the innermost
enclosing loop.  Using "break" outside
a loop results in the error:

  jump outside loop


CONTINUE

  continue

The continue statement jumps past the
remaining code within the current
iteration of a loop and immediately
proceeds to the next iteration.  Using
"continue" outside a loop also results
in the same error:

  jump outside loop


BREAK and CONTINUE example


  func count_words(line)
  {
    var i, words

    while line[i] {
      // skip runs of spaces
      if line[i] == ' ' {
        inc i
        continue
      }

      // stop counting at 20
      if  words == 20
        break

      while line[i] &&
            line[i] != ' '
        inc i

      inc words
    }

    return words
  }

  // returns 3
  count_words("the quick fox")


BARE EXPRESSION

  new_line()
  put_int(score)
  score + 1

Any bare expression is a statement (also
known as an "expression statement"), and
is most often used for function calls.

  func main()
  {
    // does nothing
    1 + 1

    /*
    calls new_line, but the
    expression itself
    is useless
    */
    new_line() + 1
  }


LEXICAL SEPARATORS

Note how there are no lexical separators
between statements.  For example, in
the C programming language, a
declaration such as

  /*
  no semicolons
  after 1 and 2
  */

  var a = 1 2

will cause an error because a semicolon
(;) does not follow the 1 and 2.  In our
case, 2 is an expression statement and
could just as well have been written
this way...

  var a = 1
  2

which is perfectly legal, if pointless.
Whether it's a lone constant, a function
call, or a binary operation between two
terms, it parses the same whether it
appears on its own line or shares one
with something else.

A function call in itself is also an
expression statement.

  var count = 1 new_line()

is the same as

  var count = 1
  new_line()

Assigning 1 to integer "count" has
nothing to do with new_line().


________________________________________


 PART 6    EXPRESSIONS
________________________________________

PRIMARY FORMS

  42              // number
  "Ready"         // string
  {1, 5, 10}      // anon array
  name            // reference
  (expr)          // grouping


POSTFIX

  arr[i]          // indexing
  f(a, b, c)      // call
  f()             // call
  arr[i][j]       // chained
  f()[0]          // call + idx
  *arr[i]()[f(j)] // complex

Indexing is word-scaled.  arr[i] is the
memory at byte address arr + i * 2.
Pointer arithmetic outside brackets
counts bytes, inside brackets it counts
words.  array[123] does not reference
the same address as 123[array].


UNARY OPERATORS

  +x      no-op
  -x      arithmetic negation
  ~x      bitwise complement
  !x      logical not (0 or 1)
  ?x      Booleanize
            (equivalent to !!x)
  @x      byte swap
  &x      address-of
  *x      fetch through an address
            (same as x[0])

  func    anonymous expression
          function

The & operator requires a storage-
denoting operand (same rule as the left
side of "let").  Strings, anonymous
arrays, bare array and function names
are addresses already and do not require
a leading &.

Example:

  var reading = 123
  var probe[4] = { &reading }

  func first_probe()
  {
    var p = probe

    // returns 123
    return &p[0][0][0]

    /*
    // also returns 123
    return ***p
    // or
    return **p[0]
    // or
    return *p[0][0]
    */
  }

The * operator reads the word that an
address points at.  It is the same
thing as writing [0]:

  *x        is        x[0]

It does no scaling of its own.  A
subscript multiplies by two because it
has an index to multiply.  * has no
index, so it fetches from wherever the
address already lands.

  var arr = {1, 2, 3}

  arr[1]          // 2
  *(arr + 1)      // 512

  /*
  512 is built from the high
  byte of element 0 and the
  low byte of element 1
  */

  *(arr + 1 * 2)  // 2, same as arr[1]

Outside brackets the count is bytes.
That rule does not bend for *.

Two identities fall out of it:

  &*x   is   x
  *&v   is   v

The first is the same trick as
&p[0][0][0] above.  The & cancels the
fetch and leaves the address behind.


FUNC

"func" acts as both a statement and a
unary operator.  As an operator, func
returns the address of an anonymous
(nameless) expression function
declaration.

Example:

  func main()
  {
    var fact
    let fact = func (n)
    {
      if n <= 1
          return 1
      return n * fact(n - 1)
    }
  }

Because anonymous functions return a
fixed address, they can be used in both
constant and local expressions.


BINARY OPERATORS

Listed from highest to lowest
precedence.  All are left-associative.

 10:        *  /  %       (signed)
  9:        <<  >>  ~>
  8:        +  -
  7:        & ^ |
  6:        <  <=  >  >=  (signed)
  5:        ==  !=
  4:        &&
  3:        ^^
  2:        ||
  1:        ,

  0:        |= ^= &=      (assignment)
            += -=
            <<= >>= ~>=
            *= /= %=

The assignment operators are listed for
completeness only.  Assignment is a
statement form, not an expression
operator (Part 5), so it cannot appear
inside a larger expression.

  let x = (y += 1)   // error

Just like the curly brackets with code
blocks and array initializers, the *
symbol has two jobs.  With a value on
its left it multiplies.  With no value
on its left it fetches.

  a * b       // multiply
  *b          // fetch
  a * *b      // multiply by the fetch

Example:

  let a = 3
  let arr = {1, 2, 3}

  put_int(a * *(arr + 2 * 2))
  // prints 9

  put_int(a * arr[2])
  // also prints 9


COMMA

As an operator, the comma evaluates the
left term, then discards it.  In
parameter lists and declarations, a
comma is read as a separator and not as
the operator unless it is surrounded by
parentheses.

  // a = 3
  var a = (1, 2, 3)

  // error
  var a = 1, 2, 3

  // good
  func save() {
    var slot
  },
  load()
    var slot

  // error
  func save2() var slot,
    load2() {
      // do something
    }

As a separator, commas are greedy.  An
inner "var a," chain will keep consuming
commas before "func" gets a turn because
var permits chaining just like func
does.  The only way to stop this is to
wrap the function's body in braces:

  func save()
  {
    let slot = 123
  }, load()
  {
    // do something
  }

"Expression statements" do not support
the comma binary operator (unless they
too are wrapped in parentheses.)

  func probe()
  {
    // error: expression expected
    123, 456

    // good
    (123, 456)

    // good
    123 456

    // not good: ) expected
    (123 456)
  }

It is worth mentioning that comma
chaining conflicts would arise if they
were permitted in expression statements.
For example, a function whose body is a
single statement (no comma-chaining
inside it) does not need braces.

  /* func chaining */

  func greet() put_str("Hello!"),
       farewell() put_str("Goodbye.")

  func add(a, b) return a + b,
    subtract(a, b) return a - b

It is a separator, and the examples
declare two functions.  A "return" never
takes the comma operator without
parentheses.

In the example below, an outer function
declares two inner functions.  No braces
are needed because the comma is not
evaluated as a binary expression.

  func split_word()
    func lo(w) return w & 255,
         hi(w) return w >> 8

A function whose body is just a local
variable declaration has no real use on
its own unless the initializer calls a
function for its side effects.  Any
comma following the var declaration
would expect another named integer
variable.

  func setup()
    // error: name expected
    var limit = 123,
    func helper()

  func setup()
    var limit = 123

So why the confusion?  What purpose does
the comma have as an operator if all it
does is discard the left-most values in
a list?  The reason is that it allows
the programmer to inject side effects
into a single expression.  Consider the
following example.

  while (clear_screen(),
    put_str("Enter command:"),
    input_str(str),
    str[0]) {
    // process command here
  }

Compared to this:

  clear_screen()
  put_str("Enter command:")
  input_str(str)

  while str[0] {
    // process command here

    // duplicate code
    clear_screen()
    put_str("Enter command:")
    input_str(str)
  }

With the comma operator, there are no
duplicates.

Both identical chunks can of course be
factored into a single function.

  func new_command(str)
  {
    clear_screen()
    put_str("Enter command:")
    input_str(str)
  }

then:

  while (new_command(str), str[0]) {
    // process command here
  }

compared to:

  new_command(str)
  while str[0] {
    // process command here
    new_command(str)
  }

There are always workarounds.  The
function "new_command" could simply
return str[0], too, but the option to
include multiple functions in one
expression can provide a viable solution
despite the confusion it sometimes
creates.


SHIFT

Shift counts are masked to 4 bits
(shifts by 0 through 15).  The "~>"
operator is arithmetic right shift
(sign-extended).  ">>" is logical right
shift (zero-filled).

  let a = 1 << 1   // a equals 2
  let b = 1 << 17  // b also equals 2
  let c = -2 >> 1  // c equal 32767
  let d = -2 ~> 1  // d equals -1


COMPARISON AND LOGICAL

Comparison and equality operators yield
0 or 1.

The logical operators (&&, ^^, ||) also
yield 0 or 1.  Any non-zero operand
counts as true.

  3 && 5     // 1, not 5
  0 || 7     // 1, not 7
  1 ^^ 2     // 0, both are true

Logical xor is defined as
(a != 0) != (b != 0).

Logical and (&&) and logical or (||)
short circuit.  The right side is not
evaluated once the left side settles the
answer.  Logical xor (^^) must inspect
both sides.  It cannot short circuit and
always evaluates both.


DIVISION AND MODULO

Division truncates toward zero.  The
remainder takes the sign of the
dividend:


  -7 /  2  =  -3
  -7 %  2  =  -1
   7 / -2  =  -3
   7 % -2  =   1


OVERFLOW

Arithmetic wraps silently on overflow.

  let a = 32767
  inc a // a equals -32767


CONSTANT EXPRESSIONS

A constant expression is one that the
compiler evaluates with constant
(non-changing) terms.  It has the same
grammar as an ordinary expression but is
evaluated at compile time.  Only the
following operands are allowed:

  numeric and character
  literals

  string literals

  anonymous array
  literals

  expression function
  literals

  names of const, enum,
  func, and global array
  declarations

  address of (&) applied
  to a global scalar, or
  to any indexed constant
  address (global array,
  anonymous array, string,
  func, const, or literal)

Addressed indexed arrays ([ ]) are
permitted in constant expressions but
calls (( )) are not.

An anonymous expression function inside
a constant expression may not reference
itself (because it's nameless), nor any
name that is not already declared.

There are no forward references, and its
own address is not yet known while its
body is being compiled.

  func start()
  {
    // error: undefined name
    put_int(num)

    var num = 123
  }

An indexed array is not a constant
expression, even when the array itself
is.  Indexing reads a value out of
memory, and values in memory can change.

  // error: not constant
  var g_first = {123}[0]

  // good
  const COIN = {1, 5, 10}

  // error
  var purse[3] =
    { COIN[2] }

Each element of an array literal follows
the same rule as a named array's
initializer.  It must itself be a
constant expression.  This holds no
matter where the literal appears, even
inside a local, non-constant expression.

  func price()
  {
    var tax

    /*
    legal.  {1, 5, 10} still
    holds constant elements, even
    though the sum is only known
    at runtime

    */
    var total =
      subtotal() + {1, 5, 10}[2]

    /*
    error.  tax is not a
    constant expression
    */
    var bad = {1, tax, 3}
  }

  // all good
  var header = {
    &node_id,
    "SENSOR-1" + 2,
    {1, 5, 10},
  }

Inside a function, indexing an array
with runtime terms is of course fine.

  func offsets()
  {
    // pick = 5
    var slot = 1
    var pick = {1, 5, 10}[slot]

    /*
    addr = base + 4
    (not the same as addr[4])
    */
    var addr = {10, 20, 30} + 4

    // value = 30
    var value = *addr

    // back = 20
    var back = addr[-1]
  }

  const THIRD = &node_id[2]

  var record[19] = {
    &123[4],
    123 + 4 * 2,
    &on_alarm[11],
    on_alarm + 11 * 2,
    77 + MAX_ROWS,
    &"SENSOR"[2],
    "SENSOR" + 2 * 2,
    THIRD,
    func (a, b) return a - b,
    &THIRD[2],
    &node_id,
    &log[23],
    log,
    'X', 'Y', 'Z',
    {1, 5, 10},
    // last two elements 0
  }

Assume tax and tmp are locals of the
enclosing function:

  var errors[8] = {
    /*
    Not constant because
    code can alter the
    memory where "SENSOR"
    is stored.
    */

    "SENSOR"[2],

    /*
    Not constant either.
    log's address is
    constant, but the
    value at address
    log + 23 * 2 is not.
    */

    log[23],

    /*
    local variable
    addresses can change
    */

    tax,
    &tax,
    &tax[2],
    tmp,

    /*
    return values for
    functions can vary,
    thus not allowed
    */

    subtotal(),

    /*
    node_id can
    be modified
    */

    node_id[2],
  }

A rule of thumb, a constant expression
must contain only terms that are
impossible to modify.  Addresses of
global variables and arrays, constants,
function names, anonymous functions
declarations, raw numbers and strings
hold a fixed value that a program cannot
change.  For instance, 10 * 15 is always
150, so it is a constant expression.
However, 3 * tax depends on what tax
holds at that very exact moment in the
program, making it a "runtime"
expression.  &node_id is constant,
because unlike local variables, its
address does not change.


________________________________________

 PART 7    SEMANTIC RULES
________________________________________

These rules are checked by the compiler
but are not part of the grammar.

ENTRY POINT

The last top-level function declared is
where the program starts, and can have
any name like "start" or "main".  It may
also have parameters which are
initialized to zero.

NO FORWARD REFERENCES

A name must be declared before it is
used.  Mutually recursive functions
require a workaround (e.g. indirect
calls through a global scalar; see
Part 9).

NO SHADOWING

A declaration cannot reuse a name
visible in an enclosing scope.

  func read_line()
  {
    var len

    func trim()
    {
      // already defined
      var len
    }
  }

LVALUE FOR let

The left side of "let" must denote
storage, like a bare scalar name, any
expression ending in brackets ([ ]), or
any expression sitting behind a *.

  let *p = 10     // same as
  let p[0] = 10

"inc" and "dec" accept the same three
forms.

  inc *p, q[0]

LVALUE FOR &

Same rule as "let".  Bare arrays,
string literals, and function names are
not lvalues since they are addresses
already.

  var scores[3]

  // error: lvalue required
  put_int(&scores)

Since * denotes storage, & undoes it.
No fetch happens:

  &*p     // p


BREAK AND CONTINUE PLACEMENT

"break" and "continue" are only valid
inside a "loop", "while" or "do-while"
loop body.

"break" and "continue" never cross a
function boundary.  It needs a loop of
its own to use.

  func poll()
  {
    loop {
      func check()
      {
        // error
        break
      }

      check()
    }
  }

PARAMETER COUNTS

Calls are not checked at compile time.
Functions may have up to 127 parameters.

FUNCTION DEPTH

Nested functions are limited to three
levels (not including the parent
function.)

STATEMENT DEPTH

Nested statements are limited to eight
levels per top-level function.

EXPRESSION DEPTH

Expression nesting is limited to eight
levels per function.

IDENTIFIER LIMITS

Identifiers may be up to 16 characters
long.  At most 128 names may be live at
once, using at most 1120 bytes of name
buffer.  Both are peaks of the scope
stack, not file totals.  Globals stay
live for the whole program, while locals
and parameters pop when their block or
function closes.

EXPRESSION FUNCTION RULES

An anonymous expression function may
contain other definitions or expression
functions, but not statement (named)
function declarations.

Expression function definitions do not
chain with commas, unlike statement
function definitions.  Inside a constant
expression, an expression function may
not reference itself (because it's
nameless) or any name not already
declared.

FUNCTION EXIT VALUES

"return" requires an expression. "leave"
never takes one.  A function that falls
off the end of its body returns zero.
Every exit path yields a defined value.


________________________________________

 PART 8    SYSTEM CALLS
________________________________________

The Nine programming language has no
builtin system call keyword.  Instead
a "stub" is used, which is just an array
whose values are "opcodes," and is then
called like an ordinary function.


DECLARING A STUB

  /*
  ENTER 0x04 0x00 0x0000
  SYS   0x00
  LEAVE 0x04 0x00
  */


  var sys_call[5] = {
    0x040E,
    0x0000,
    0x0100,
    0x0F00,
    0x0004,
  }

The same can be done with a string.

  var sys_call = "\x40E\x0\x100"
                 "\xF00\x4"

Then:

  sys_call(SYS_PUT_CHAR, buf)

"buf" is a small array or variable used
to pass values in and out.  When a call
takes one parameter, the address-of
operator can be used with a scalar.

When a call takes no parameters, the
second argument is ignored.  By
convention, pass 0:

  sys_call(SYS_CLEAR_SCREEN, 0)

or just

  sys_call(SYS_CLEAR_SCREEN)


CALL NUMBERS

  enum {
    SYS_EXIT,           //  0

    SYS_KEY_READY,      //  1
    SYS_GET_KEY,        //  2

    SYS_CLEAR_SCREEN,   //  3
    SYS_PUT_CHAR,       //  4

    SYS_GOTO_XY,        //  5
    SYS_PUT_CHAR_XY,    //  6

    SYS_READ_TIMER,     //  7
    SYS_SET_TIMER,      //  8

    SYS_COM_STATUS,     //  9
    SYS_READ_COM,       // 10
    SYS_SEND_COM,       // 11

    SYS_PEEK_EEPROM,    // 12
    SYS_POKE_EEPROM,    // 13

    SYS_PEEK_SCRATCH,   // 14
    SYS_POKE_SCRATCH,   // 15
  }


CONVENTIONS

In the descriptions below:
  <-  value passed
  ->  value returned


CALL REFERENCE

SYS_EXIT
  End the program and return
  to the editor.  No
  parameters.

SYS_KEY_READY
  -> buf[0]  1 if a key has been
             pressed, else 0

SYS_GET_KEY
  -> buf[0]  get character

  Blocks until a key is
  available.

SYS_CLEAR_SCREEN
  Clear the text screen.  No
  parameters.

SYS_PUT_CHAR
  <- buf[0]  character to write

  Teletype-style output.  The
  cursor advances. '\n', '\r',
  and '\b' are interpreted as
  control characters.

SYS_GOTO_XY

  <- buf[0] x (0 to 39)
  <- buf[1] y (0 to 24)

  Moves the cursor to an x
  and y coordinate.
  Out-of-range coordinates
  hide the cursor.

SYS_PUT_CHAR_XY
  <- buf[0]  character to write
  <- buf[1]  x (0 to 39)
  <- buf[2]  y (0 to 24)

  Places a character at an x
  and y coordinate.  Control
  characters are not
  interpreted.  Every value
  is placed on screen as a
  glyph.  Out-of-range
  coordinates are ignored.
  Character glyph is inverted
  if bit 15 is set (| 0x8000).

SYS_READ_TIMER
  -> buf[0]      100 Hz timer value

SYS_SET_TIMER
  <- buf[0]      100 Hz timer value

SYS_COM_STATUS
  -> buf[0]      returns COM port
                 status

  Serial Port Status values:

  COM_DATA_READY =        0x0001
  COM_OVERRUN_ERROR =     0x0002
  COM_PARITY =            0x0004
  COM_FRAMING_ERROR =     0x0008
  COM_BREAK_DETECT =      0x0010
  COM_HOLD_EMPTY =        0x0020
  COM_REGISTER_EMPTY =    0x0040
  COM_TIMEOUT =           0x0080


SYS_READ_COM
  -> buf[0]      character from the
                 COM port
                 returns -1 if
                 timeout

SYS_SEND_COM
  <- buf[0]      character to the
                 COM port

SYS_PEEK_EEPROM
  <- buf[0]      EEPROM address to
                 peek (read)
  -> buf[1]      value peeked

  "EEPROM" is an area of 512
  16-bit nonvolatile memory
  locations.

SYS_POKE_EEPROM
  <- buf[0]      EEPROM address to
                 poke (write)
  <- buf[1]      value to poke


SYS_PEEK_SCRATCH
  <- buf[0]      scratch address
                 to peek (read)
  -> buf[1]      value peeked

  "scratch" is an area of 2048
  16-bit temporary memory
  locations.

SYS_POKE_SCRATCH
  <- buf[0]      scratch address
                 to poke (write)
  <- buf[1]      value to poke


SERIAL PORT

The COM port operates at 9600 bps, 8
data bits, no parity, 1 stop bit (8N1).
This applies to SYS_READ_COM,
SYS_SEND_COM, and to the editor's ^K U /
^K D commands (see Editor Reference,
Part 9).


EEPROM

EEPROM is an area of 512 16-bit
permanent memory locations.  Reading or
writing outside the address space
triggers the runtime error:

  invalid EEPROM address

Example:

  poke_eeprom(511, 9999)
  put_int(peek_eeprom(511))
  // prints 9999

  poke_eeprom(512, 1234)
  // error

Writing to EEPROM memory is slow and has
a limited number of writes, usually
around 100,000 before the memory begins
to degrade.  It is meant to be used
sparingly for data that does not change
frequently.

Any value written to an EEPROM memory
address is internally verified with a
"read-back."  The following error occurs
if the values do not match.

  EEPROM parity error


SCRATCH RAM

The scratch RAM is an area of 2048
temporary 16-bit memory locations.  This
space is zeroed before a run.  Reading
or writing outside the address space
results in the runtime error:

  invalid scratch address

Example:

  poke_scratch(2047, 0x9999)
  put_int(peek_scratch(2047))
  // prints -26215

  poke_scratch(2048, 0x1234)
  // error


HALTING A RUNNING PROGRAM

  var halt = 0x0034
  (&halt)()

or

  var halt[1] = {52}
  halt()

or

  var halt = {52}
  halt()

  "\x34"()

or

  ({52})()

0x34 is the opcode for the halt
instruction.  Halt works in almost the
same way as SYS_EXIT, except that halt
does not display the message

  0x0000: system exit

before returning to the editor.

Because SYS_EXIT equals zero, both
parameters may be omitted.

  sys_call() /* exits program */


________________________________________

 PART 9    IDIOMATIC PATTERNS
________________________________________

OUTPUT ONE CHARACTER

  func put_char(c)
  {
    sys_call(SYS_PUT_CHAR, &c)
  }


PRINT A STRING

  func put_str(s)
  {
    var i

    while s[i] {
      put_char(s[i])
      inc i

    }
  }


PRINT A SIGNED INTEGER

  func put_int(n) {
    if n == -32768 {
      put_str("-32768")
      leave
    }

    if n < 0 {
      put_char('-')
      let n = -n
    }

    if n >= 10
      put_int(n / 10)
    put_char('0' + n % 10)
  }


FUNCTION POINTER

  var draw = put_char_xy
  draw('*', x, y)


POINTER DEREFERENCE

  var row = screen + y * 40

  // word at row
  row[0]
  // or
  *row

  // word at row + (x * 2)
  row[x]
  // or
  *(row + x * 2)


MUTUAL RECURSION WORKAROUND

Since forward references are not
allowed, two mutually recursive
functions need an indirect call through
a global:

  var _is_odd

  func is_even(n)
  {
    if n == 0
      return 1

    return _is_odd(n - 1)
  }

  func is_odd(n)
  {
    if n == 0
      return 0

    return is_even(n - 1)
  }

  func start()
  {
    let _is_odd = is_odd

    // prints 1
    put_int(is_even(10))
  }

Another method is to pass the forward
reference as a pointer and then call it:

  func apply(fp, n)
  {
    return fp(n)
  }

  func square(n)
  {
    return n * n
  }

  func start()
  {
    // prints 49
    put_int(apply(square, 7))
  }


PASS-BY-REFERENCE

To modify a caller's scalar, pass its
address and dereference with [0]:

  func swap(p, q) {

    var tmp = p[0]

    let p[0] = q[0]
    let q[0] = tmp
  }

  func start() {
    var a = 1, b = 2

    swap(&a, &b)
    /* a = 2, b = 1 */
  }


STRING COPY, WORD INDEXING

A subscript counts WORDS: arr[i] is the
word at byte address arr + i * 2.  The
doubling is automatic.

  func str_copy(dst, src) {
    var i

    while src[i] {
      let dst[i] = src[i]
      inc i
    }
    let dst[i] = 0
  }


STRING COPY, POINTER STEPPING

Arithmetic on the address itself counts
bytes.  One word is two bytes, so the
pointers advance by 2.  Parameters are
ordinary locals and may be reassigned.

  func str_copy(dst, src) {
    while src[0] {
      let dst[0] = src[0]

      let src = src + 2
      let dst = dst + 2

      /*
      // also works
      inc src, src
      inc dst, dst
      */
    }

    let dst[0] = '\0'
  }

or

  func str_copy(dst, src) {

    while (src + i)[0] {
      let (dst + i)[0] =
        (src + i)[0]
      let i = i + 2
    }

    let (dst + i)[0] = '\0'

When a compiler error happens, a brief
message appears at the bottom of the
screen following a line number.

  L1234: too many elements

Pressing Enter repositions the cursor to
the offending line.  Pressing Esc or
Space returns to the original cursor
location.

In the same manner, a "runtime" error
also produces a message following an
address, in hexadecimal, of where in
memory the error was produced.

  0x04D2: divide by zero

Pressing Enter, Esc or Space returns
to the editor at the last cursor
position.  In order to locate the
runtime error, print function addresses.

  func average(total, n)
  {
    /* divide by zero if n is 0 */
    return total / n
  }


  func start()
  {
    put_hex(average)
    average(100, 0)
  }

This method is obviously not perfect.
There is no debugging line information
placed alongside code during the
compiling phase.  Printing addresses or
scattering halts in suspect areas should
give some idea of where a runtime error
originated.

The code generated from named functions
is stored in the "code" memory area, and
sized local arrays are copied from code
memory to the stack area.  Anonymous
functions, string literals and anonymous
arrays (where opcodes may be) all reside
in "data" memory.

Other errors form when certain limits
are reached.   Below is an example of
how "deep" nested functions, statements
and expression can go.

var f0 = +++++++func ()
{
  var f1 = +++++++func ()
  {
    var f2 = +++++++func ()
    {
      var f3 = +++++++func ()
      {
        {
          {
            {
              {
                var v0 = +++++++1
              }
            }
          }
        }
      }
    }
  }
}

Adding a new nested function will
trigger the compiler error:

  too many nested functions

Nine restricts nested functions to three
levels deep, not including its parent
function.

Adding another plus (+) to the series of
pluses halts with the error:

  too many nested expressions

Nested expression counts are clamped at
eight per function.

Adding one more nested statement or
nested block results in the error:

  too many nested statements

Nested statements also max-out at eight
per top-level function, that is, the
parent function must have no more than
eight nested code blocks total.

func f0()
{
  { // level1
    { // level2
      func f1()
      { // level3
        func f2()
        { // level4
          { // level5
            { // level6
              { // level7
                func f3()
                { // level8
                }
              }
            }
          }
        }
      }
    }
  }
}

func draw_line(x0, y0, x1, y1, c)
{
  var dx, dy, sx, sy, err, e2

  if x1 > x0
    let dx = x1 - x0, sx = 1
  else
    let dx = x0 - x1, sx = -1

  if y1 > y0
    let dy = y1 - y0, sy = 1
  else
    let dy = y0 - y1, sy = -1

  let err = dx - dy

  loop {
    put_char_xy(c, x0, y0)

    if x0 == x1 && y0 == y1
      break

    let e2 = err * 2

    if e2 > -dy {
      let err -= dy
      let x0  += sx
    }

    if e2 < dx {
      let err += dx
      let y0  += sy
    }
  }
}

func project_vertices(ax, ay)
{
  var cx = cosine(ax)
  var sx_r = sine(ax)
  var cy = cosine(ay)
  var sy_r = sine(ay)
  var v

  while v < 8 {
    var px, py, pz

    if v & 1
      let px =  CUBE_R
    else
      let px = -CUBE_R

    if v & 2
      let py =  CUBE_R
    else
      let py = -CUBE_R

    if v & 4
      let pz =  CUBE_R
    else
      let pz = -CUBE_R

    var rx  = (px * cy +
      pz * sy_r) ~> 5
    var rz  = (pz * cy -
      px * sy_r) ~> 5

    var ry2 = (py * cx -
      rz * sx_r) ~> 5
    var rz2 = (rz * cx +
      py * sx_r) ~> 5

    var z_off = rz2 + DIST
    if z_off < 8
      let z_off = 8

    let vx[v] = (rx  * FOCAL
      / z_off) + CX
    let vy[v] = (ry2 * FOCAL
      / z_off) + CY

    inc v
  }
}

func mandel(cr, ci)
{
  var zr, zi, zr2, zi2, n

  while n < MAXITER {
    if zr > LIMIT || zr < -LIMIT
      break

    if zi > LIMIT || zi < -LIMIT
      break

    let zr2 = (zr * zr) ~> FBITS
    let zi2 = (zi * zi) ~> FBITS

    if zr2 + zi2 >= FOUR
      break

    let zi = ((zr * zi) ~> HALF) + ci
    let zr = zr2 - zi2 + cr

    inc n
  }

  return n
}

func plot()
{
  var py

  while py < ROWS {
    var px = 0
    var ci = Y0 + py * DY

    while px < COLS {
      var n = mandel(X0 + px * DX, ci)

      put_char_xy(shades[n], px, py)
      inc px
    }

    inc py
  }
}

func input_str(str, len)
{
  var c
  var i

  do {
    let c = wait_key()

    if c >= ' ' && c <= 127 {
      if i < len {
        let str[i] = c
        put_char(c)

        inc i
      }
    }
    else if c == '\b' {
      if i {
        backspace()
        dec i
      }
    }
    else if c == 27 {
      if !i
        break

      while i {
        backspace()
        dec i
      }
    }

  }
  while c != '\r'

  let str[i] = '\0'
  return i
}

func put_hex(n)
{
  if n & 0xFFF0
    put_hex(n >> 4)

  put_char(hex_chars[n & 15])
}

func new_line()
{
  put_char('\r')
  put_char('\n')
}

func set_seed(s)
{
  if s
    let seed = s
  else
    let seed = read_timer() | 1
}

func get_rand()
{
  let seed ^= (seed << 7)
  let seed ^= (seed >> 9)
  let seed ^= (seed << 8)

  return seed
}
